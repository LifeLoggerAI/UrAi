# Original UrAi — observed code architecture and integration boundaries

**Exact main source:** `8cac3ba513830c11261d57bc2b5dd7ad8b83e85a`. Source existence is not executed runtime evidence.

## Application planes
- **Public and demo shell:** Next.js 15 / React 19 app. `src/app/page.tsx` (blob `0adc0e64011ff3b959343996d1051d2cbbbe93ae`) actually renders `LaunchPage kind="home"` from `src/components/launch/LaunchShell.tsx` (blob `079c7c7b2c5f8021f8e92cfe69af72fc6756dab9`). The older `docs/URAI_CANON.md` root-HomeScene assertion is stale relative to this pinned implementation.
- **Spatial Home:** `src/app/app/page.tsx` → `src/components/urai/home/HomeScene.tsx` (blob `4d7daf9af6da4c818bc89d365ae5ca8be5a6e167`) → `src/components/urai/GenesisSceneShell.tsx` (blob `3aa66d3673dcc43683a9c350a5ca57bf6131b395`) / Three fiber canvas and portal navigation. `HomeScene` ignores its `ascentTarget` prop, supplies empty 3D canvas child and no-op navigate/Orb callbacks: this path's intended ascent/Orb interaction is not source-complete.
- **Memory galaxy:** `src/app/life-map/page.tsx`, `src/app/focus/page.tsx`, and app-scoped `src/app/app/life-map/{page,focus/page,replay/page}.tsx` render `src/components/spatial-life-map/SpatialLifeMap.tsx` (blob `ad170b90575b763954bffedb538f40df6abbf376`). It composes `LifeGalaxyScene`, star selection, zoom/camera and focus overlay; Replay button routes to root `/replay`, and `initialMode="replay"` lacks an independent Replay body at this component. Actual root `src/app/replay/page.tsx` (blob `68bbcc8541eab2ecb779d368a1a4acb0fed91b9d`) openly renders a protected-media-free *sample preview*.
- **Data:** `src/components/spatial-life-map/useLifeMapData.ts` (blob `fb0d2949ce61c3508582f3fe5b3063030f8aefee`) and `src/lib/spatial-life-map/lifeMap.firebase.ts` (blob `e5144b1fd8a2cf5eb71c018aec18430a4d2f4a35`) use owner-shaped Firestore paths under `users/{userId}/` for lifeMapStars, constellations, layers, chapters, memoryBlooms, relationshipThreads, ritualThreads and spatialSettings/default. Fallback to mock data occurs when unconfigured, missing essential records or read failures. The demo component defaults to `userId="demo-user"`; authenticated production owner binding must not be inferred.
- **Other preserved realms:** `src/app/app/council/page.tsx` → `src/components/urai/council/CouncilWorld.tsx`; `src/app/app/mirror/page.tsx` → `src/components/life-map/LifeMapUniverse.tsx` with Mirror overlay; separate `src/components/passport/`, `shadow/`, `replay/`, `urai/humans/`, `urai/real3d/`, `urai/home/HomeXRInteractionLayer.tsx` remain tracked. These are distinct implementation families and cannot be conflated with current `urai-spatial` live capability.
- **Companion and trust:** `src/app/api/companion/route.ts` (blob `835f2b83f11d2e57378034b090b6dc34d04b38b9`) calls deterministic `buildCompanionReply`, not a verified production AI model. `src/app/api/spatial/consent/route.ts` (blob `f3aa31442f4dc16d47fcefc1a9274bf6225e0a6e`) is a static-export placeholder, not signed positive consent.
- **Two competing waitlist paths:** Public `LaunchShell.tsx` calls browser `src/lib/launch/firebaseClient.ts` (blob `9e58cbbd279a6ba1f58983f838bd0db89821451a`) to write `waitlistEntries` / `analyticsEvents` with Firebase client; `src/app/api/waitlist/route.ts` (blob `e482061425213bd70d452bd4a0cbc77abd2f943a`) uses Firebase Admin for `waitlistSignups`, with optional dry-run. The README's server-only waitlist assertion is therefore not true of all source paths. Determine effective Rules/production endpoint before asserting an actual access defect.

## Authority / cross-repo topology
- Canonical consumer immersive runtime and production orchestration: **`LifeLoggerAI/urai-spatial` / `urai-tier1`** (not this legacy repo).
- Governance, subject rights, signed consent: `urai-privacy`; guarded asynchronous work: `urai-jobs`; life movies/exports: `urai-studio`; staging: `urai-staging`; control plane: `urai-admin`; schema/content: `urai-content`; assets: `asset-factory`; professional RuAi: `B2Bportal`; separate analytics, communications, storytime and organizational estate repos.
- Do not assert a real `Privacy → Studio → Jobs → protected Spatial Replay` connection without final-head, signed, authenticated, revocation/deletion-safe integration receipts.
- `docs/CROSS_REPO_DEPENDENCIES.md` blob `8420e97015ce41f18e1b5350c6390f3367c4225d` is useful historical crosswalk but predates current production authority.

Home → Ascent → Life Map → Focus → Replay → Escape → Focus → Life Map → Home. Verify actual user-owned memory media, star-to-star focus, accessibility, privacy, hardware and content transitions on the *canonical spatial build*, not by promoting the legacy demo shell.
