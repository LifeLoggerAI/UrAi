- At `functions/src/ancientScheduledRollups.ts` blob `96591813cc8e0d5dacfe51e14b8ac5faaffe5996`, `userAllowsAncientSignals(userData)` returns false **only** when specific feature flags or `userData.consents.healthWellnessInsights` are explicit `false`; otherwise it returns `true`. **Missing positive consent is therefore treated as eligible.** In the same file `writeScheduledAncientSignalRollup` persists `consentBasis: {healthWellnessInsights: true}` regardless of a cryptographic/purpose-scoped owner consent issuer.

At `functions/src/ancientPassiveRollups.ts` blob `072324cb20bd67deca55f3934b9c1017bc72fe1f`, Firestore Admin queries restrict by `ownerUid` but do not independently check active consent/revocation. The historical scheduled processing thus lacks today's fail-closed consent security needed for sensitive owner inference.
- **Threat assumption:** restoration of these pre-quarantine Functions and real personal sources. **Source verdict:** a concrete **latent/dormant consent-bypass design in historical code**, **not** proof of active exposure or any deployed incident. Preserve the source and prevent unreviewed reintegration. The correct new path is governed `urai-privacy` positive signed consent + source provenance + revocation, not tweaking a legacy scheduler into production.
